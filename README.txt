ОБНОВЛЕНИЕ ДЛЯ ОБЛАЧНОЙ ВЕРСИИ (Render + Supabase) - работает целиком из браузера рабочего ноутбука
================================================================================================
Зачем: чтобы облако перестало «то работает, то нет». Всё бесплатно, личный компьютер не нужен.

ПОЧЕМУ БЫВАЛО ТО РАБОТАЕТ, ТО НЕТ (проверено по документации Render и Supabase)
- Бесплатный сервис Render засыпает через 15 минут без запросов, первый заход после этого ждёт ~минуту.
- Бесплатные 750 часов Render в месяц выдаются на ВСЕ сервисы аккаунта. Один сервис круглосуточно
  (~720 ч) помещается, ДВА - нет: тогда Render приостанавливает все бесплатные сервисы до конца месяца.
- Диск Render стирается при каждом перезапуске (а Render может перезапустить бесплатный сервис в любой момент).
- Бесплатный проект Supabase уходит на паузу после недели без обращений к базе. Резервных копий на
  бесплатном тарифе Supabase нет.
- Старая версия при сбое Supabase молча подменяла данные пустой базой и могла затереть настоящие.

ЧТО ИСПРАВЛЕНО В ПРОГРАММЕ
1. Сервер сам обращается к себе каждые 9 минут (не засыпает) и раз в 12 часов делает лёгкий запрос
   к Supabase (проект не уходит на паузу). Отключение: переменная KEEP_ALIVE=0.
2. Если Supabase не отвечает, сервер НЕ подменяет данные пустой базой: он ждёт, переподключается сам,
   пока ждёт - отвечает «подключаюсь, повторите» (страница студента сама повторяет отправку ответов).
   Данные в Supabase не затираются (проверено тестами с имитацией сбоев).
3. Неудавшееся сохранение повторяется (3 попытки сразу + досылка каждые 15 секунд), а при остановке/
   перезапуске сервиса последнее состояние дописывается в Supabase.
4. Секрет входа и пароль админ-панели хранятся в самой базе: после перезапуска Render преподавателей
   больше не «выкидывает». Пароль админки при создании печатается в журнале Render (Logs).
5. Адрес /health (без пароля, без личных данных) - «живой» ли сервер и подключена ли база. В панели
   преподавателя справа внизу индикатор: «● Сервер на связи» / «⚠ База данных подключается…» / «✖ Нет связи».

ШАГИ (один раз, ~10 минут)
1. Render (dashboard.render.com): в списке сервисов должен остаться ОДИН рабочий сервис (quiz-b2b-final).
   Старый второй сервис (quiz-b2b) удалите или приостановите (Settings -> Suspend/Delete Web Service).
2. Supabase (supabase.com/dashboard): проверьте, что проект активен. Если «Paused» - нажмите Resume project.
3. GitHub: в репозитории загрузите файлы из этого архива с заменой (Add file -> Upload files):
      server.js, db.js, package.json
      public/index.html, public/student.html    (в папку public)
   Остальные файлы проекта не трогайте. Нажмите Commit changes.
4. Render пересоберёт сервис сам (Auto-Deploy). Если нет: сервис -> Manual Deploy -> Deploy latest commit.
5. Переменные окружения (Render -> сервис -> Environment): SUPABASE_URL и SUPABASE_SERVICE_KEY должны
   быть заданы (у вас уже есть). ADMIN_PASSWORD и SESSION_SECRET задавать не обязательно. Если нужен
   свой пароль админки - добавьте ADMIN_PASSWORD. Если пользуетесь платформой только вы (никто чужой
   не должен регистрироваться) - добавьте REGISTRATION=first-only (регистрация закроется после
   первой учётной записи).
6. Проверка: откройте  https://ВАШ-СЕРВИС.onrender.com/health  - должно быть  "ok":true  и  "ready":true.
   В панели преподавателя внизу справа должно гореть «● Сервер на связи».
7. Тариф: если ваша учётная запись на бесплатном тарифе (лимиты на тесты/сдачи), в админ-панели
   (/admin) поставьте ей план «unlimited».

ПЕРЕД КАЖДЫМ ЗАНЯТИЕМ (10 секунд)
Откройте панель преподавателя: индикатор должен быть зелёным. Если жёлтый «База подключается» -
подождите минуту. Если долго жёлтый - в Render откройте Logs: строка «Supabase недоступен» значит
проект на паузе (Resume project в Supabase) или неверный ключ.

ЧЕСТНО ОБ ОГРАНИЧЕНИЯХ
- Бесплатный Render не гарантирует непрерывность: он может перезапустить сервис в любой момент.
  Теперь это занимает секунды и ничего не теряет (данные в Supabase, вход сохраняется, студенты
  повторяют отправку), но иногда студент увидит «подождите 10-20 секунд».
- Самопинг рассчитан на то, что Render учтёт запрос к своему же адресу как входящий. Если после простоя
  первая загрузка всё равно долгая - добавьте внешний бесплатный пингер (например cron-job.org):
  запрос GET на  https://ВАШ-СЕРВИС.onrender.com/health  каждые 10 минут.
- РЕЗЕРВНЫЕ КОПИИ: у бесплатного Supabase их нет. Раз в неделю (и перед важными занятиями) скачивайте
  копию: /admin -> «Скачать бэкап базы», сохраняйте файл на диск/в OneDrive. Восстановление - там же.
- Данные студентов хранятся на внешних серверах (Render/Supabase) - убедитесь, что это допустимо по
  правилам предприятия.

ОТКАТ, ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
Render -> сервис -> Events/Deploys -> Rollback на предыдущий деплой (доступно для двух последних).
Формат данных не менялся (добавлен только служебный раздел meta, старая версия его игнорирует).

ЛОКАЛЬНАЯ ВЕРСИЯ
